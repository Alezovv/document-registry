# DocumentRegistry — Руководство по сборке, публикации и управлению версиями

Документация описывает полный цикл сборки портативного приложения **DocumentRegistry**, публикацию обновлений в Google Drive, а также работу системы обновлений вперёд и отката на предыдущие версии с сохранением базы данных.

## 1. Архитектура управления версиями

В приложении реализованы два режима работы с версиями в разделе **«Настройки → Обновления и управление версиями»**:

| Режим | Кнопка в интерфейсе | Назначение и поведение |
| :--- | :--- | :--- |
| **Обновление вперёд (основной)** | `Проверить обновления` (+ автопроверка при запуске и раз в час) | Сверяет текущую версию с полем `version` на верхнем уровне `manifest.json`. Если доступна более новая версия (`candidate > current`), предлагает скачать и установить её. |
| **Откат на старую версию (дополнительный)** | `Откат на старую версию` | Открывает диалог выбора предыдущих версий (`candidate < current`) из массива `versions` в `manifest.json`, локального кэша или выбранного вручную `.zip`-пакета, показывает описание версии (`notes`) и проверяет различия в БД. |

### Что происходит с базой данных при откате

1. **Анализ различий (`compare_database_for_rollback`)**:
   - Проверяется версия схемы текущей базы данных (`PRAGMA user_version`) относительно схемы выбранной старой версии (`database_schema`).
   - Проверяется наличие таблиц и колонок более новых версий (например, `request_parser_metadata`, `source_sha256`, `source_size_bytes` в схеме `v7`, таблиц полнотекстового поиска `request_fts` и `request_search_content` в схеме `v6`, поля `is_pinned` в `v5`, `completed_date` в `v4`, `due_date` в `v3`, `snapshot` в `v2`).
   - Подсчитывается количество записей, использующих новые поля, а также проверяются расхождения данных с предыдущей резервной копией БД.
2. **Предупреждение пользователя**:
   - Если обнаружены различия в схеме или данных, программа выводит подробное предупреждение со списком отличий и запрашивает подтверждение перед началом отката.
3. **Автоматическое сохранение текущей базы данных**:
   - Перед переходом на более старую версию текущая база данных (с которой выполняется переход) автоматически сохраняется и проверяется через `PRAGMA integrity_check` в папку `backups/rollback/`:
     - Файл базы SQLite: `backups/rollback/requests_before_rollback_v<текущая>_to_v<целевая>_<дата_время>.db`
     - Метаданные перехода: `backups/rollback/requests_before_rollback_v<текущая>_to_v<целевая>_<дата_время>.json`
     - Полный архив резервной копии (БД + документы + корзина): `backups/rollback/full_backup_before_rollback_v<текущая>_to_v<целевая>_<дата_время>.zip`
4. **Адаптация схемы БД под старую версию (`downgrade_database`)**:
   - Если выбранная старая версия использует более раннюю схему БД (`target_schema < current_schema`), рабочая база автоматически приводится к целевой схеме с полным сохранением всех записей и общих полей, чтобы старая сборка открыла базу без ошибок несовместимости.

## 2. Подготовка к сборке новой версии

Перед запуском сборки нового релиза (например, при переходе с `1.28.5` на `1.28.6`) убедитесь, что номер версии синхронизирован в трёх местах (это проверяется автоматическими тестами при сборке):

1. **`app/__init__.py`**:
   ```python
   __version__ = "1.28.6"
   ```
2. **`packaging/build.ps1`** (значение параметра `$Version` по умолчанию в начале файла):
   ```powershell
   param(
       [string]$Python = "python",
       [string]$Version = "1.28.6",
   ```
3. **Тесты проверки текущей версии в папке `tests/`**:
   Если вы поднимаете номер версии, обновите строку версии в тестах одной командой PowerShell из корня проекта:
   ```powershell
   Get-ChildItem .\tests\test_*.py | ForEach-Object {
       (Get-Content $_.FullName -Raw).Replace('"1.28.5"', '"1.28.6"') | Set-Content $_.FullName -Encoding UTF8
   }
   ```

## 3. Пошаговая инструкция по сборке и публикации релиза

### Шаг 1. Активация окружения и запуск сборки

Откройте PowerShell в корне проекта `C:\document-registry` и выполните:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& .\venv\Scripts\Activate.ps1
Unblock-File -Path .\packaging\build.ps1

.\packaging\build.ps1 -Version 1.28.5 -PublishTo "C:\DocumentRegistry_Publish" -ReleaseNotes "Описание изменений версии 1.28.5"
```

*(Если виртуальное окружение находится в `.venv`, укажите `& .\.venv\Scripts\Activate.ps1`).*

Что сделает скрипт на этом шаге:
- Запустит полную проверку проекта `verify_project.py --full` и все unit-тесты.
- Соберёт через PyInstaller основное приложение `DocumentRegistry.exe` и автономный установщик `DocumentRegistryUpdater.exe`.
- Выполнит предрелизные самопроверки (`--self-check`, `--ocr-self-check`, `--ner-self-check`).
- Создаст готовый портативный архив в `release\DocumentRegistry_v1.28.5_portable.zip`.
- Сформирует в `C:\DocumentRegistry_Publish\` версионный пакет обновления **`DocumentRegistry_1.28.5_update.zip`** (со встроенным `update_manifest.json` и описанием релиза).

### Шаг 2. Загрузка пакета обновления на Google Drive

1. Откройте публичную папку обновлений на Google Drive (ссылка указана в `app/update_config.py` в `UPDATE_DRIVE_FOLDER_URL`).
2. Загрузите туда файл **`C:\DocumentRegistry_Publish\DocumentRegistry_1.28.5_update.zip`**.
3. **Важно**: **не удаляйте** из папки Google Drive ZIP-файлы предыдущих версий — они нужны для того, чтобы программа могла скачивать старые сборки при откате.
4. Нажмите правой кнопкой мыши на загруженный `DocumentRegistry_1.28.5_update.zip` → **Поделиться (Share)** → выберите доступ **«Все, у кого есть ссылка»** → скопируйте ссылку.
5. Извлеките `file_id` из скопированной ссылки:
   ```text
   https://drive.google.com/file/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/view?usp=sharing
                                   ^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                   Это ваш PackageFileId
   ```

### Шаг 3. Генерация финального `manifest.json`

Выполните команду с параметром `-ManifestOnly`, подставив скопированный `PackageFileId`:

```powershell
.\packaging\build.ps1 -Version 1.28.5 -ManifestOnly -PublishTo "C:\DocumentRegistry_Publish" -PackageFileId "<СКОПИРОВАННЫЙ_ID_ФАЙЛА>" -ReleaseNotes "Описание изменений версии 1.28.5"
```

При выполнении этой команды скрипт:
- Прочитает локальный `C:\DocumentRegistry_Publish\manifest.json` и автоматически скачает текущий опубликованный `manifest.json` с Google Drive.
- Перенесёт предыдущую актуальную версию (вместе с её `package_file_id`, `sha256`, `size`, `database_schema` и описанием `notes`) в массив `"versions": [...]`.
- Запишет новую версию `1.28.5` на верхний уровень `C:\DocumentRegistry_Publish\manifest.json`.

### Шаг 4. Обновление `manifest.json` на Google Drive

1. В папке Google Drive нажмите правой кнопкой мыши на существующий файл **`manifest.json`**.
2. Выберите **«Управление версиями» (Manage versions)** → **«Загрузить новую версию» (Upload new version)**.
3. Выберите файл `C:\DocumentRegistry_Publish\manifest.json`.

> **Важно**: всегда обновляйте существующий файл `manifest.json` через «Управление версиями», а не удаляйте его, чтобы его постоянный идентификатор `UPDATE_MANIFEST_FILE_ID` в `app/update_config.py` оставался неизменным.

## 5. Работа пользователя с обновлениями и откатом

### Как откатиться на предыдущую версию
1. Откройте в программе вкладку **«Настройки»** и найдите карточку **«Обновления и управление версиями»**.
2. Нажмите дополнительную кнопку **«Откат на старую версию»**.
3. В открывшемся окне выберите нужную версию из выпадающего списка (список загружается автоматически из `manifest.json` на Google Drive; при отсутствии интернета можно нажать **«Выбрать пакет (.zip)…»** и указать локальный файл `DocumentRegistry_<версия>_update.zip`).
4. Ознакомьтесь с описанием выбранной версии и блоком проверки совместимости базы данных.
5. Нажмите **«Откатиться на выбранную версию»**. Если в базе данных есть различия, подтвердите предупреждение — программа сохранит текущую БД в `backups/rollback/`, скачает пакет старой версии и выполнит установку.

### Как после отката снова подняться на актуальную версию
1. Откройте **«Настройки → Обновления и управление версиями»** и нажмите основную кнопку **«Проверить обновления»** (либо дождитесь автоматической проверки при запуске).
2. Программа прочитает верхний уровень `manifest.json`, обнаружит актуальную версию и предложит штатно обновиться вперёд.
3. При необходимости вернуть состояние базы данных, сохранённое непосредственно перед откатом, откройте **«Настройки → Резервное копирование → Восстановить из копии»** и выберите архив `backups\rollback\full_backup_before_rollback_...zip` (или импортируйте `.db`-файл из `backups\rollback\`).
